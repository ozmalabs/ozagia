# Ozagia feature inventory

Inventory audited 2026-11-17 against `main` and registered worktrees; plan and feature statuses reconciled 2026-11-24 against the code. Ozagia is an alpha local workbench for AI-assisted development, operations and research. Its graph, tools, workflows and operational controls support model reasoning; Ocelot is a separate optional cognitive engine. Features below describe the current checkout, including unreleased development work, rather than promising that every feature is enabled, fully integrated or production-ready. The final section distinguishes unmerged or uncommitted work. See [the integration analysis](docs/ozagia_capability_integration_analysis.md) for how these features can work together.

A central aim is to do the prompting and context-assembly work for the operator: provide relevant project knowledge, task boundaries, instructions and checks through the workflow itself. A sufficiently prompted model with the right context may perform similarly without Ozagia; the intended difference is that Ozagia makes those supports repeatable by construction, rather than depending on operator skill or luck. Individual integrations and workflows provide different degrees of that support, and comparative performance remains an evaluation question.

## Repository understanding and context

- **Project indexing and graph:** index files, symbols, tests, documentation, imports, references, commits and other project facts; configurable roots, exclusions and project-specific adapters; stable node keys and typed relationships; persistent snapshots and freshness checks. Incremental reingestion, graph deltas, watched adapter inputs, caches and parallel extraction support refresh after changes. [Graph surface](docs/graph_surface.md), [symbol graph](docs/symbol_graph.md).
- **Language support:** optional tree-sitter tags for Python, Rust, Lua, C, C++, Go, Java, JavaScript, TypeScript and TSX, subject to installed grammars and their query coverage. Import supplied SCIP JSON definitions and references; optional language-server navigation and diagnostics. [Languages](docs/tag_languages.md), [SCIP](docs/scip.md), [LSP](docs/lsp.md).
- **Search and navigation:** lexical/BM25 search fused with graph ranking; ranked repository maps whose task mode scores exact identifiers, demotes support files, and fuses bounded content candidates with confidence weighting, snippet tiers and an evidence gate; retrieval evaluation reports evidence coverage and density alongside recall and precision; find nodes, inspect and expand neighborhoods, find callers and callees, and estimate change impact. Structured JSON, YAML and TOML path queries and outlines are supported where applicable. [Search](docs/code_search.md), [repo map](docs/repo_map.md), [symbol graph](docs/symbol_graph.md).
- **Application profiling and telemetry:** read existing cProfile/pstats, Speedscope/py-spy, Chrome/Node CPU, folded `perf`/stackcollapse, OTLP JSON trace/metric and Prometheus text artifacts; normalize durations, samples, histograms and counters; join active frames to graph definitions, callers and impact; rank hotspots, hot paths, files/modules, service operations, metrics and baseline regressions. Optional guided collection runs one explicitly approved cProfile, py-spy or Node command under resource admission and rlimits; artifact ingestion remains offline and read-only over the target. Deep review can consume profile reports as measured evidence. [Profiling](docs/profiling.md).
- **Architecture analysis:** graph summaries, hubs, strongly connected components, coupling, modules, test-to-source ratios and heuristic dead-code candidates. Results reflect available graph coverage. [Architecture](docs/architecture_summaries.md).
- **Context delivery:** task-aware graph hints, source attribution, session-start briefs, working sets, graph refresh after edits, read ledgers, repeat-read notes and optional stubs, outline-first reads, path resolution and cross-session ownership hints. Capture varies by harness. [Intent](docs/intent.md), [sessions](docs/session.md).
- **API mappings:** index selected OpenAPI operations and explicit mappings between APIs and code; optional YAML support. [API mappings](docs/api-mappings.md).
- **Extensibility:** per-project configuration and adapter registry for indexers, graph queries, edit engines and MCP tools; target projects are not imported. [README](README.md).
- **Federated graphs:** search and node inspection across independently indexed checkouts, automatic discovery of indexed immediate siblings or explicit membership, qualified node identities, snapshot provenance and declared cross-repository links. Queries may first update explicitly designated reference repositories; they do not index other repositories or infer semantic relationships. [Federation](docs/federation.md).
- **Cross-repository checks:** declared API relationships and operation method/path comparisons, service identity comparisons, and current-source observations of explicitly linked Python environment reads against Kubernetes environment names. Reports preserve provenance and uncertainty; they do not run contract or deployment tests. [Checks](docs/cross-repo-checks.md).
- **Reference repositories:** explicitly designated references are checked for safe origin fast-forwards by default unless pinned; session briefs report update and graph freshness where supported. Updates are bounded and do not overwrite dirty or divergent checkouts. [Federation](docs/federation.md).

## Editing and development workflows

- **Structured edits:** graph-addressed Python AST and symbol operations, Rust and Lua CST operations, Markdown sections, JSON paths, HCL blocks and attributes, and optional comment-preserving YAML edits; span and key-based editing, parse guards and reference checks where supported. [CST edits](docs/cst_edit.md), [IaC edits](docs/iac_edit.md).
- **Edit transactions:** preview by default, content/base-hash checks, recheck before write, atomic replacement, state-directory backups, edit journal and preservation of relevant text properties; diagnostics and lint feedback where configured. [Intent](docs/intent.md).
- **Interactive tool handling:** graph-aware handling of supported reads, searches, file operations, edits, patches and shell command forms; fallback to the host tool for unsupported cases. Includes structured queries, selected `jq` and shell operations, compound-command handling, edit-miss recovery and permission integration where the harness supports it. [Intent](docs/intent.md).
- **Tests:** graph-aware affected-test planning with none, smoke, affected, package and all policies; mandatory previously failing, flaky and changed tests in applicable modes; captured pytest selection, test-result caching, failure tracking and test-to-graph mappings. Plans do not themselves establish that tests passed. [Testing](docs/testing.md).
- **Lint:** bounded changed-line feedback after supported edits using configured Ruff or rustfmt, plus selected Ruff command capture; trust and timeout controls. [Intent](docs/intent.md).
- **Development sessions:** record plans, steps, edits, checks and decisions in a replayable session graph; working-set briefs and session events support continuity. [Session graph](docs/session.md).
- **Library-first hints:** detect possible opportunities to use existing dependencies or standard-library functionality, provide evidence and optional session capture; advisory, not an automatic dependency decision. [Library hints](docs/library_hints.md).

## Tasks, goals and review

- **Bounded tasks:** versioned TOML/JSON task specifications with declared inputs, tools, path scopes, output schemas, budgets, stop conditions and gates; deterministic preflight, typed steps, injected executor, evidence records and optional explicitly enabled local executor. The runner itself does not call a model or access the network. [Tasks](docs/tasks.md).
- **Task catalogue:** built-in task classes for diff review, impact analysis, repository scanning, test triage, config validation, log inspection, model classification, claim extraction, evidence tables, manuscript checks, paper triage, reference screening and theory comparison; inspect and copy specifications. [Task library](docs/task_library.md).
- **Goals:** persistent repository-level goals with graph targets, permitted scope, claims by sessions, statuses, machine-checkable criteria and evidence-based evaluation; review findings can be turned into goals and reevaluated for regressions. [Goals](docs/goals.md).
- **Code review:** deterministic, graph-aware review of changes, evidence and test-impact context; optional model review and optional Ocelot structural grouping where explicitly selected. [Code review](docs/code_review.md).
- **Whole-repository review:** typed packets covering architecture, tests, health, churn and ownership, documentation, security, operations and dependencies; compare findings across reviews and report what was not assessed. Findings are candidates, not verified verdicts. [Repository review](docs/repo_review.md).
- **Deep review:** compose an offline-by-default, subject-based report (security, performance, failure modes, data structures, scalability, architecture, tests and coverage, dependencies, operations, docs/API and correctness) from repository review, security scanning, static Python candidates, dependency/operations inventories and documentation checks; record per-subject checks, omissions, unknowns, graph freshness, budgets, truncation, evidence excerpts, report hashes and output hashes in a manifest; compare exact finding IDs against a previous report with subject/severity deltas and gate with `--fail-on`. `--profile change`/`review-change` is a compact `HEAD~1..HEAD` preset; `--range` adds change-set review; `--profile-report` adds measured profile evidence; `--security-tool`/`--security-network` explicitly select scanners and network access with per-tool provenance. Local dependency licence/version inventory and `sbom.json` record CVE state as unknown; an explicit local advisory file can match exact locked versions or OSV-style introduced/fixed ranges without fetching data or proving a dependency clean (ranges support Node/Rust strict SemVer, `v`-prefixed Go and Python PEP 440; Ruby, Composer and Maven remain exact-version only). `ozagia-status` has a read-only reviews section. Tests are not run and the target is not imported; optional `--model-pass` requires live gates, applies role mapping, validation, dedupe and time/request/token/cost budgets, and writes advisory, unverified candidates that never block; optional Ocelot clustering is candidate-only with exact fallback. [Deep review](docs/deep_review.md).
- **Repository scan and module scaffolding:** advisory ranked development opportunities from graph, git and local state; preview-first scaffolding plans with review gates, explicit application, tests and rollback considerations. [Repo scan](docs/repo_scan.md), [module build](docs/module_build.md).
- **Model configuration:** discover locally advertised OpenCode models, configure defaults and task-specific choices, and explain selection. Selection is deterministic; the registry is not an autonomous model router. [Models](docs/models.md).
- **Model graph and metadata:** advisory model families, capabilities, similarity and task/tool matching; optional explicitly imported or fetched provider metadata with cache, provenance and staleness. Matching does not automatically route requests or prove a model's task performance. [Model graph](docs/model_graph.md), [metadata sources](docs/model_sources.md).
- **Project Python environments:** discover interpreters and declared dependencies, map source imports to environments, recommend environments for files and surface dependency gaps. Project-shipped interpreters require explicit trust before probing; static discovery has limits. [Environments](docs/environments.md).
- **Failure classification and evaluation timing:** distinguish test, collection, environment, harness and timeout causes; connect interpreter evidence to failure reports and goal assessment; record available per-component, per-task and amortized evaluation timings. Missing measurements remain unknown. [Evaluation](docs/eval_agent.md), [environment and timing plan](docs/plans/2026-11-17_env_failures_timing.md).

## Research and scientific workflows

Research and combined modes are opt-in; research records and extracted candidates do not automatically establish scientific truth. [Research overview](docs/research.md).

- **Research graph and provenance:** represent sources, references, claims, evidence, assumptions, notation, derivation links, model candidates, relationships, user positions and review findings; preserve source locators, hashes, provenance, status and explicit holdings that distinguish evidence, interpretation, hypothesis and other roles. [Sources](docs/research/sources.md), [positions](docs/research/positions.md).
- **Ingestion and retrieval:** selected TeX, Markdown, text, HTML, EPUB, PDF, TEI/JATS and bibliography inputs; BibTeX, BBL, CSL-JSON and RIS references; full-text search and optional vector/hybrid search. PDF extraction can use available backends and optional OCR; extracted claims and equations have documented limitations. [PDF](docs/research/pdf.md), [research](docs/research.md).
- **Reference acquisition:** open-access metadata and artifact resolution via supported providers, content-addressed caching, citation metadata checks and reference export; optional external providers and fetch fallback. Bibliographic citation links do not by themselves prove evidential support. [Providers](docs/research/providers.md).
- **Evidence synthesis:** screening decisions and reports, extraction tables, source-linked evidence tables, risk-of-bias and certainty appraisals, contradiction candidates, retraction and citation alerts, and living-review records. [Synthesis](docs/research/synthesis.md).
- **Theory comparison:** record theories, assumptions and predictions, rivalries and compatibility; compare shared and unique evidence and whether recorded evidence discriminates between theories. [Theory](docs/research/theory.md).
- **Structured and multi-model review:** review plans, evidence packets, independent reviewer records, agreement and dissent, reconciliation, steelman/red-team arguments, review-finding ledgers and cross-session closure. Model execution is handled by separate explicitly invoked harnesses. [Review](docs/research/review.md), [paper review](docs/research/paper_review.md).
- **Manuscript and formula workflows:** manuscript checks and export bundles, formula candidates and interpretation, optional symbolic tooling, and Lean export where supported; outputs require review and do not establish arbitrary paper correctness. [Research](docs/research.md).
- **Research views:** read-only library, fetch, screening, evidence, consensus and citation views, with JSON/HTML presentations. [Research UI](docs/research_ui.md).
- **Ocelot integration:** explicit resolution and optional installation of a separate Ocelot checkout; optional structural reconciliation of research reviews and clustering/analogy for code findings, test impact and architecture patterns. Ozagia does not bundle Ocelot or automatically install it. [Ocelot](docs/ocelot.md), [code integration](docs/ocelot_code.md).
- **Ozma protocol research:** preserved model-interface specifications, shim and map designs, reviews and selected historical implementation for Ozagia's future interface work. This is a design basis, not a claim of implemented protocol conformance. [Protocol research](docs/research/ozma_protocol/README.md).

## Infrastructure and operations

- **Infrastructure graph:** experimental opt-in source-level Terraform/OpenTofu, Kubernetes, Helm, Kustomize, CloudFormation, ARM, Pulumi YAML, CDK assembly and GitOps context; discovery, dependencies, impact, status and findings. Analysis is partial and does not imply live deployment state. [IaC context](docs/iac_context.md).
- **IaC checks and edits:** offline pre-plan checks, source-level HCL/YAML edits, diagnostics and SARIF-oriented output; offline AWS CLI validation and declared environment profiles. [IaC checks](docs/iac_check.md), [IaC edits](docs/iac_edit.md), [AWS validation](docs/aws_cli_validation.md).
- **Operations records:** bounded, redacted receipts and resumable handoffs, experimental operations graph, supplied live-state snapshot import/diff and offline preflight plans. [Operations](docs/sre_operations.md), [ops graph](docs/ops_graph.md), [live state](docs/live_state.md).
- **Jobs, relays and runtime:** opt-in live job waiting, background daemon jobs, declarative services and processes, local/SSH/SSM relay chains and tunnels, with explicit live gates and policies; configuration alone does not start a service or establish a connection. [Jobs](docs/jobs.md), [relay](docs/relay.md), [runtime](docs/runtime.md).
- **Action layer:** read-only status and preview-first actions for daemon, services, tunnels and integrations; mutations consume a confirmation token. [Actions](docs/actions.md).
- **Log inspection:** bounded local log reading, redaction, grouping, ranking and reviewable proposals, including a bounded task specification. [Log inspection](docs/log_inspect.md).
- **Toolchain discovery:** detect supported external tools and optional Python libraries, report capability readiness and explain install options without installing them; daemon, session brief, MCP and OpenCode panel surfaces provide task context where supported. [Toolchain](docs/toolchain.md).

## Workspace, resources and safety

- **Worktrees and Git:** inspect expected worktrees, branch and upstream drift, filesystem placement and commit/merge/push policy; dry-run pruning, optional Git hooks and secret gate. The checker reports or gates configured actions; it does not itself create, move or remove worktrees. [Worktrees](docs/worktree.md).
- **Resource visibility and admission:** inspect available memory, swap, disk, filesystem and tmpfs, CPU/load and available Linux pressure/process data; estimate admission for work and record bounded resource history. Unknown measurements are reported as unknown. [Resources](docs/resources.md).
- **Job limits:** on supported Linux systems with delegated cgroup v2, daemon background jobs can enforce memory and process limits and track job-attributed disk writes; fallback uses rlimits and a verified process-group watchdog where available. Coverage depends on platform, permissions and configured limits; this is not a guarantee that the host cannot run out of resources. [Resources](docs/resources.md).
- **File lifecycle:** created-file ledger with attribution, Markdown routing, preview-first cleanup to recoverable state-directory trash, restore and explicit purge. [Files](docs/files.md).
- **Security scanning:** offline graph and source antipattern findings, dependency inventory, secrets checks and optional external scanners; staged/diff scopes, configurable gates and opt-in hooks. Findings are triage evidence, not proof of exploitability or security. [Security](docs/security.md).
- **Consent-based diagnostics:** preview and explicitly export redacted local field-improvement bundles or issue drafts; no automatic reporting or upload. [Upstream](docs/upstream.md).

## Interfaces, configuration and distribution

- **Agent integrations:** OpenCode capture plugin and harness; Claude Code, Codex and Kiro hooks and MCP integrations with differing capture coverage; native agent loop for an OpenAI-compatible API. Integration and live-test maturity vary. [Harness](docs/harness.md), [Claude Code](docs/claude_code.md), [Codex](docs/codex.md), [Kiro](docs/kiro.md), [native loop](docs/native_loop.md).
- **MCP and APIs:** coding, research and combined modes; graph-oriented tool surface, CLI commands and Python library APIs; optional stateful engine surface with compact rows, token budgets, `known` deltas and bounded fork-isolated background speculative handles with a thread fallback; a reusable stdlib HTTP client for that engine (automatic session and op-scoped `known` deltas, plus the session-independent Ozma `task_context` provider call); optional Ozma context integration. [MCP](docs/memory_mcp.md), [graph surface](docs/graph_surface.md), [engine](docs/graph_engine.md), [Ozma](docs/ozma_integration.md).
- **Views and user interfaces:** graph view models, configurable apertures and static HTML; unified status snapshot; standalone read-only console; OpenCode add-in with graph, status, research, settings, testing, task catalogue and preview-first action/task controls. [Views](docs/view.md), [status](docs/status.md), [console](docs/console.md), [add-in](docs/opencode_addin.md).
- **Configuration:** typed settings registry, validation, precedence and provenance across defaults, user and repository configuration, environment and explicit overrides; preview-first writes and legacy configuration migration. [Settings](docs/settings.md).
- **Install and self-management:** source/package installation and bundled installer with pinned components; self info, checks, upgrades and uninstall; release tooling. Parsers, language servers and other integrations are optional dependencies. [Install](docs/install.md), [release](docs/release.md).
- **Evaluation:** retrieval benchmarks, leakage-aware task sets, index benchmarks, IaC benchmarks, Hugging Face tagged-benchmark ingestion (SWE-bench Verified/Lite gold-file retrieval) and end-to-end agent break/fix evaluation with different backends and arms. Live model drivers require explicit live enablement and human approval; benchmark downloads require explicit network approval. Results are workload-specific and do not establish universal speed or accuracy gains. [Retrieval eval](docs/eval_retrieval.md), [agent eval](docs/eval_agent.md), [HF benchmarks](docs/eval_benchmarks.md), [results](docs/results/).

## Work in progress outside this checkout

Worktree state is a point-in-time observation, not a release promise. Many registered worktrees are historical branches whose commits are already merged; being listed as a worktree does not mean a feature is pending.

- **Secrets by reference:** `src/ozagia/core/secrets.py` is on `main` with `tests/test_secrets.py` and [docs/secrets.md](docs/secrets.md): typed `secret://` refs, `env`/`file` and optional `keyring`/`pass`/`op` providers, a redactor, an in-memory session store, and resolution at runtime-service, background-job and daemon boundaries. The OpenCode Desktop add-in now has a native-`secret` prompt, a pending-request composer pill, and provide/decline commands that send the value to `ozagia-secrets fulfill --stdin` without putting it in argv, RPC output, logs or plugin state ([design](docs/plans/2026-11-17_session_secrets_ui.md)); this is offline-tested. The actual Desktop dialog, host RPC logging and host storage ordering are unverified live, so no end-to-end host canary run yet establishes that a secret never reaches model context.
- **Toolchain context:** the formerly separate `feat/toolchain-context` work was merged while this audit was underway; daemon, session brief and MCP integration are part of current `main`. Recheck branch ancestry before treating another registered worktree as unmerged.
