## What this is

**ozagia**

**Ozma advanced graph integration agent.** A live code graph for LLM coding agents: index a repository into typed nodes (files, symbols, tests, docs, imports, call edges), keep it current while the agent edits, and put it in the agent's path. MIT licensed. Status: alpha. The library, the MCP server, the OpenCode capture plugin and the agent harnesses work; the Claude Code, Codex and Kiro hooks are implemented but untested against a live host. Measurements are in `docs/results/`; plans in `docs/plans/`; release sequencing and the current plan audit in [`docs/roadmap.md`](docs/roadmap.md). A generated reference for this repository's own shape (layout, modules, docs, entry points and commands) is [`REPO_SHAPE.md`](REPO_SHAPE.md), produced by `ozagia overview` ([docs/repo_shape.md](docs/repo_shape.md)).

README sections: `Install`, `What it does`, `Ways to use it`, `Quick start (from source)`, `Configuring a repository`, `Research mode`, `Origin`, `Development`.

README highlights:

- **Graph index**: files, symbols, tests, docs, imports, git history and known failures as one graph snapshot, with project-specific nodes added by adapters.
- **Retrieval**: ranked repo map (PageRank over references), fused lexical and graph code search, symbol-level callers, callees and impact, architecture summary. Optional language-server refinement (pyright, rust-analyzer).
- **Graph-addressed edits**: Python symbol and AST ops, Rust/Lua CST ops, Markdown section ops, JSON path ops, HCL block/attribute ops and optional comment-preserving YAML path ops. Preview by default, base hash check, atomic write, backup. A diff is output only, never input.
- **Review**: deterministic review of a commit range (`ozagia-review`) or of the whole repository (`ozagia review-repo`: import cycles, test gaps, dead symbols, stale doc references, security hygiene, ops sources, lock files), with stable finding ids and graph keys. No model calls.
- **Deep review**: `ozagia deep-review` composes an offline-by-default, subject-based report across security, performance, failure modes, data structures, scalability, architecture, tests, dependencies, operations, docs/API and correctness; per-subject coverage, bounded `evidence/` excerpts, `findings.json`, a manifest, baseline deltas and a caller-selected `--fail-on` gate. `--profile change` (alias `review-change`) is a compact `HEAD~1..HEAD` range preset; `--range` adds change-set review and `-...
- **Evals**: a leakage-checked retrieval eval, a break/fix agent eval with selectable agent backends (OpenCode, Claude Code), and an index bench.
- **Profiles**: `ozagia profile` reads existing cProfile, Speedscope/py-spy, Chrome/Node CPU, folded `perf`, OTLP trace/metric and Prometheus text artifacts; joins active frames to graph symbols, callers and impact; and reports hotspots, paths, service operations, metrics and baseline changes. `ozagia profile run --allow-exec` collects one explicitly approved cProfile, py-spy or Node run under the resource policy. Offline by default ([docs/profiling.md](docs/profiling.md)).
