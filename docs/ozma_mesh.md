# Ozma mesh bridge

`ozagia mesh ozma` maps a local [session mesh](session_mesh.md) identity to a
host-supplied Ozma agent identity, reports whether the bridge is configured and
ready, and (from Stage G) queues typed messages and advisory claims in durable
local stores.  `status`, `map` and `check` remain read-only and never touch the
network.  The local mesh remains the source of truth, and a mapping is never an
authorization for a claim, merge, wake or message.

The upstream Ozma specification and the Rust `ozma-mesh` project are not
clients of this module.  This repository ships no Ozma server, shim, A2A
adapter or Agent Card verifier.  A configured shim URL is recorded as
configuration only; until a shim contract exists, `check --live` reports
`live_not_configured` and contacts nothing.  The bridge envelope below is a
**closed local schema**, and its mapping is **declared, not upstream-verified**.
No command in this slice opens a socket, runs DNS or HTTP, or falls back to a
hosted service.

## Configuration

The bridge reads one owned section, `[ozma_mesh]`, from `.ozagia.toml` or
`ozagia/config.toml` (the usual project-config precedence applies).  It is off
by default:

```toml
[ozma_mesh]
enabled = false
mode = "off"                 # off | status | messages | full
transport = "native"         # native | a2a
shim_url = ""                # loopback/approved; empty means no network
allow_remote = false
auth_ref = ""                # secret://... reference only, never a value
flight_id = ""               # empty -> the local mesh id
agent_id = ""                # host-provided; never generated
agent_scope = "workspace"    # workspace | user | global
card_path = ""
card_fingerprint = ""        # sha256:<64 hex> of the local card file
verified_by = "host"         # host | none
wake_modes = ["passive"]     # passive | message-triggered | scheduled
channels = []
subscriptions = []
priority_floor = 0.3
queue_max_messages = 200
queue_max_bytes = 262144
outbox_ttl_s = 86400
ack_timeout_s = 60
dedupe_window_s = 86400
message_rate = "60/5min"
```

Unknown keys are rejected.  Enumerations, list sizes and numeric bounds are
checked, so a typo cannot silently disable a limit.

`agent_id` is supplied by the host and is never invented or generated by
Ozagia.  If it is set it must look like `agent:<role>[:<workunit>]`.
`flight_id` must be a bounded mesh-style id; when empty it defaults to the local
mesh id (`[mesh] id`, or `default`).  Different flights never share mapping
records.

`card_fingerprint` must be `sha256:` followed by 64 hex characters.
`auth_ref` must be a `secret://...` reference; an inline credential is
rejected without echoing the rejected value.  A non-empty `shim_url` must be
`http(s)` on `localhost`, a `*.localhost` name, or a loopback IP unless
`allow_remote = true`.  Even then, this slice never uses it.

`mode` cannot exceed `status` while the host has not supplied both an
`agent_id` and a `card_path`; use `mode = "status"` until they are present.

Wake modes are declared, not granted.  `passive` is the default.  A
`message-triggered` or `scheduled` entry is reported, but it cannot spawn a
turn or spend a model budget in this slice.

## Identity and card rules

A local Ozagia identity is `{harness, session, key}`.  The key comes from an
existing local mesh registration when one is supplied, otherwise from the same
deterministic session-key function.  `--harness`/`--session` or
`OZAGIA_MESH_HARNESS`/`OZAGIA_MESH_SESSION` name it.

An Ozma identity is the host-provided agent id, scope, card path, fingerprint,
transport and flight id.  `status`, `map` and `check` never create an agent id,
thread id, priority, capability or lease.

The bridge hashes the local card file and compares it with
`card_fingerprint`.  The comparison reports one of:

- `match`: the bytes of the card file match the configured digest.
- `mismatch`: the digest differs; the bridge is never ready.
- `missing`: no card, no card path, or no configured fingerprint.
- `unknown`: the card path is a symlink, is not a regular file, or cannot be
  read.

No signature verification or PKI check is available here.  A matching digest
plus `verified_by = "host"` is reported as `host_declared`: the host asserted
the identity, but the result is not cryptographically verified and is not
message-ready on that basis alone.

## Commands

```text
ozagia mesh ozma status [--json] [--harness H --session S]
ozagia mesh ozma map [--save] [--json] [--harness H --session S]
ozagia mesh ozma check [--require-ready] [--live] [--json]
                       [--harness H --session S]
ozagia mesh ozma outbox [--all] [--json]
ozagia mesh ozma inbox [--unread] [--json] [--harness H --session S]
ozagia mesh ozma read MESSAGE_ID [--json]
ozagia mesh ozma ack MESSAGE_ID [--accepted|--rejected] [--reason R]
                       [--json] [--harness H --session S]
ozagia mesh ozma claims [--json]
ozagia mesh ozma flight [--limit N] [--json] [--harness H --session S]
ozagia mesh ozma handoff list|show [HANDOFF_ID] [--json]
ozagia mesh ozma handoff accept|reject|complete HANDOFF_ID [--reason R]
                       [--json] [--harness H --session S]
ozagia mesh ozma block --blocked ID --blocker ID [--workunit W] [--resource R]
ozagia mesh ozma unblock [--id ID] [--workunit W] [--json]
ozagia mesh ozma blockers [--json]
ozagia mesh ozma wake list [--json]
ozagia mesh ozma wake approve --mode M --budget-turns N [--ttl S]
                       [--agent ID] [--json] [--harness H --session S]
ozagia mesh ozma wake revoke APPROVAL_ID [--json] [--harness H --session S]
ozagia mesh ozma wake claim [--json] [--harness H --session S]
ozagia mesh ozma enqueue --message LOCAL_MSG_ID [--channel C]
                          [--offer-as response|handoff]
                          [--harness H --session S]
ozagia mesh ozma claim --lease LEASE_ID [--merge] [--harness H --session S]
ozagia mesh ozma sync [--json]
```

`status` reports the overall state, transport, flight, agent id presence,
card fingerprint state, scope, wake modes, channel and subscription counts,
queue bounds and `network: false`.  It reads local configuration and local
files only.

`map` prints the Ozagia → Ozma identity mapping and the transport loss table.
Without `--save` it only reads.  `--save` writes one mapping record at
`<state dir>/mesh/ozma/identities/<hash(flight_id, ozagia key)>.json`; the
directory is `0700` and the file `0600`, written atomically.  A record contains
the schema, flight id, local identity, agent id/scope/card reference,
verification status/source, transport, wake modes, channels, subscriptions,
status and timestamps.  It never contains a credential value.

`check` validates readiness for the configured mode.  `--require-ready` exits
`1` when the mode is not ready.  `--live` is accepted for forward
compatibility but reports `unavailable` / `live_not_configured` and does not
call out.

Exit status is `0` for a well-formed report, including `missing` and
`unverified`; `1` only for `check --require-ready` when the mode is not ready;
and `2` for invalid configuration, arguments or local IO.

## Readiness states

| State | Meaning | Ready for |
| --- | --- | --- |
| `off` | `enabled = false`, or `mode = "off"` | `off` only |
| `missing` | no host-provided agent id or readable card | `status` |
| `mismatch` | the card digest does not match `card_fingerprint` | never |
| `unverified` | the card has no matching host declaration | `status` |
| `host_declared` | digest matches and `verified_by = "host"` | `status` only |
| `ready` | reserved for a future explicit host verification flag | future |
| `unknown` | the card fingerprint cannot be determined | never |

`host_declared` is deliberately not message-ready.  There is no hidden
verification flag in this slice, so `mode = "messages"` or `mode = "full"`
reports not ready with a reason rather than pretending a card was verified or
that a message could be delivered.

A missing agent id or card is not an error for `status`; it stays `missing`
and never triggers generation of an id or a state write.

## Transport loss

Native Ozma transport is the normative path.  A2A v1.0 is an interop adapter,
and the bridge marks it `lossy: true` with the fields it cannot represent:

- `criteria`
- `claim_scope`
- `blockers`
- `subscriptions`
- `priority_floor`
- `compliance`
- `refs` when a ref is present
- `workunit` when a workunit is present

`map` and `check` list the static fields.  The A2A adapter adds `refs` and
`workunit` to its own `loss_fields` when the envelope carries them.  No verified
handoff, claim or completion is implied under A2A or native transport.

## No-network boundary

`status`, `map` and `check` are read-only with respect to the network:
`network` is always `false`.  There is no implicit discovery, no hosted
fallback, no outbound message and no model call.  `shim_url` is validated and
reported only by presence and host class (loopback/remote); it is not
contacted.  A future live slice needs an approved shim contract, explicit
authentication supplied by the host, and its own opt-in.

## Stage G: declared messages, claims and inbox

Stage G adds the local half of a bidirectional bridge.  It translates typed
messages and advisory claims, stores them atomically below
`<state dir>/mesh/ozma/`, deduplicates replays and exposes the inbox.  It does
**not** implement an Ozma transport.  The mapping and envelope are a local
declaration; conformance is reported as `declared` and `unverified`.

### Bridge envelope (`schema: 1`)

The envelope is closed: unknown envelope fields and unknown typed body fields
are rejected rather than dropped.

```json
{
  "schema": 1,
  "bridge": "ozagia.ozma_bridge",
  "flight_id": "default",
  "id": "msg_0123456789abcdef",
  "type": "request",
  "direction": "outbound",
  "from": "agent:reviewer:wu1",
  "from_card": "sha256:<64 hex>",
  "in_reply_to": null,
  "thread": null,
  "refs": [],
  "priority": null,
  "deliver_at": null,
  "requires_ack": null,
  "compliance": [],
  "channel": "#flight",
  "workunit": null,
  "body": {"purpose": "general", "text": "bounded local text"},
  "body_trust": "untrusted",
  "created_at": "2026-11-26T00:00:00Z",
  "expires_at": "2026-11-27T00:00:00Z",
  "digest": "sha256:<canonical content digest>"
}
```

`digest` is the SHA-256 of canonical sorted-key JSON with `digest`,
`created_at` and `expires_at` excluded, so a re-enqueued or retried message
keeps the same id and digest.  `id`, `in_reply_to`, `thread`, `refs`,
`priority`, `deliver_at`, `requires_ack`, `compliance` and `channel` are
validated and preserved when present.  `from` and `to` must be host-provided
`agent:<role>[:<workunit>]` ids; a local session key is never used as an Ozma
id.  A direct local message needs a saved peer mapping in the same flight; a
broadcast needs an explicit configured channel (or the single configured
channel when there is exactly one).  `hello` is identity metadata and is
rejected as a peer message.

The declared local → Ozma table is:

| local kind | Ozma type | note |
| --- | --- | --- |
| `hello` | — | identity/card metadata; never a peer message |
| `request` | `request` | `purpose` general/review/question |
| `accept` | `ack` | `{accepted:true}` |
| `reject` | `ack` | `{accepted:false, reason}` |
| `offer` | `response` or `handoff` | the caller chooses; the choice is recorded |
| `status` | `status` | text only |
| `release` | `release` | `in_reply_to` the claim id |
| `note` | `heads-up` | bounded untrusted text |
| `block`/`unblock` | `block`/`unblock` | reason/resource |
| `handoff` | `handoff` | workunit/criteria/refs/completion |
| lease (`worktree`/`branch`/`path`/`merge`) | `claim` | advisory; `merge` is never authority |
| lease (`grant`) | — | local-only, `unsupported` mapping |

Free-form local text is carried only as bounded text in `request`, `response`,
`heads-up`, `status` or an `ack` reason, with `body_trust: "untrusted"`.  A
typed verdict (such as `accepted`) is never fabricated.  Inbound text is
redacted on ingest and always marked untrusted; it is content, not a command.

### Outbox

`<state>/mesh/ozma/outbox/<flight>/<hash>.json` stores one envelope per
outbound message.  The filename is a hash of `(flight, message id, direction)`;
no raw id or path appears in it.  States are `pending`, `sent`, `acked`,
`expired` and `failed`; an attempt counter is kept and a retry reuses the same
id.  `outbox_ttl_s` is reported as `expired`, never deleted automatically.

The outbox is bounded by `queue_max_messages` and `queue_max_bytes`, and
`message_rate` is enforced over its trailing window.  A full queue or exceeded
rate refuses with `queue_full` or `rate_limited`; pending and failed rows are
never dropped.  When a new row needs capacity, the oldest terminal rows
(`sent`, `acked`, `expired`, or an already-expired pending row) yield first and
the eviction count is reported.  A message larger than the byte cap is refused
before anything is evicted.

### Inbox, dedupe and redaction

`<state>/mesh/ozma/inbox/<flight>/<hash>.json` stores inbound envelopes with
`unread`, `read` or `acked` state.  List views return metadata only
(id/from/type/channel/created/expires/priority/requires_ack/read/acked); a body
comes only from an explicit `read`.  Ingest redacts text, marks it untrusted,
caps size and refuses when the configured caps are reached.  Unread mail is
never evicted; acked mail (and read mail that does not require an ack) yields
only when a new message needs capacity, with the eviction count reported.

Replay is keyed by `(flight_id, ozma_message_id, direction)` through a bounded
dedupe index.  The same id with the same digest is a no-op; the same id with a
different digest is `id_conflict`, counted and never replayed.  The window is
`dedupe_window_s`.  A conflict is reported, not resolved by overwriting.

`ozagia mesh ozma inbox` merges the Ozma inbox with the local mesh mailbox in
the read view only.  Remote entries are tagged `origin: ozma`; local entries
`origin: local`.  Remote messages are never injected into a local mailbox and
no local session is impersonated.  `mesh inbox`/`mesh read` remain local-only.

### Claims and conflicts

Outbound claim refs and inbound **remote claims** live in
`<state>/mesh/ozma/claims/<flight>/<hash>.json`.  A local lease maps to a
declared claim scope:

- `worktree` → `worktree`;
- `branch` → `branch`;
- `path` → `file` (or `subtree` for a directory-shaped path);
- `merge` → `branch`, always advisory;
- `grant` → unsupported: a grant is local-only.

A remote claim records its holder agent id/card fingerprint, scope, resource,
mode, expiry, digest and state.  It is **not** a local lease and can never
block local work, a local merge request or local merge policy.  The bridge
reports a warning when a remote claim and an active local lease name the same
resource, but the local lease remains usable.  Expiry is computed and reported
from the record; records are not auto-deleted or overwritten.  A remote claim is
released only by a matching remote `release` from its holder (or its own
rules).  The advisory claim store is bounded; a new claim beyond the cap is
refused with `claim_store_full`, while a replay of an existing claim is still
accepted.

### Channels and subscriptions

A message may carry a channel only from the configured `channels` list; an
off-scope channel is refused on ingest.  Subscriptions may be:

- a bare channel such as `#flight`;
- `channel:#name`;
- `workunit:<id>`;
- `event:<local-kind>` (for example `event:request`);
- `type:<ozma-type>` (for example `type:heads-up`).

Inbound messages must satisfy the configured subscriptions (when any) and the
`priority_floor`.  There is no implicit `#general` channel, no external channel
adapter and no write to Slack or another service.

### Shim, `sync` and live

The transport seam is deliberately tiny:

```python
class Shim:
    def deliver(self, envelope) -> {"accepted": bool, "message_id": str | None}: ...
    def poll(self, after, limit) -> [envelope, ...]: ...
```

Production and the CLI use `UnavailableShim`, which raises `shim_unavailable`
and never opens a socket.  `sync` delivers pending/failed outbox rows with
their existing ids, then ingests a bounded poll with dedupe, conflict, channel
and claim handling.  A fake in-process shim exists only in tests; there is no
CLI flag that enables a network shim.

`check --live` remains `unavailable`/`live_not_configured`.  `sync` reports
`shim_unavailable` and exits `1` without network access.

### CLI examples

```text
ozagia mesh ozma status --json
ozagia mesh ozma outbox --all
ozagia mesh ozma inbox --unread --harness opencode --session a
ozagia mesh ozma read msg_0123456789abcdef
ozagia mesh ozma ack msg_0123456789abcdef
ozagia mesh ozma claims
ozagia mesh ozma enqueue --harness opencode --session a \
  --message msg_0123456789abcdef --channel '#flight' --offer-as response
ozagia mesh ozma claim --lease lease_0123456789abcdef --merge \
  --harness opencode --session a
ozagia mesh ozma sync
```

`enqueue` and `claim` need a registered local identity with `coordinate`
exposure, bridge mode `messages` or `full`, a matching host-declared card and
a valid flight.  Read views (`outbox`, `inbox`, `read`, `claims`, `flight`,
`handoff list|show`, `blockers`, `wake list`) need no identity.  A typed `ack`
is an explicit CLI choice; a handoff acknowledgement needs a host/coordinate
session; `wake approve|revoke|claim` are CLI-only host primitives (no MCP or
daemon action).  Errors use stable codes such as `bridge_not_ready`, `queue_full`,
`rate_limited`, `id_conflict`, `channel_not_allowed`, `unsupported_mapping`,
`unknown_message`, `shim_unavailable`, `wake_not_approved`,
`wake_budget_exhausted`, `wake_expired`, `wake_not_due` and
`a2a_unsupported_required`; bodies and credentials are never echoed in an
error.

`status` adds read-only bridge counts: outbox pending/sent/failed/expired,
inbox unread/read/acked, remote/outbound claims, active/expired claims,
conflict count, queue messages/bytes against caps, dedupe conflicts, handoff
states, open/cleared blocker edges and wake approval/request counts.  The core
`ozagia status` snapshot also carries a compact `flight` section with counts
only.  Neither `status`, `check` nor any read view creates
`<state>/mesh/ozma`.

## Stage H: declared flights, handoffs, blockers, A2A and wake primitives

Stage H adds a flight view and local lifecycle primitives.  It is still the
declared local half of the bridge: the envelope mapping is `declared`, the
identity result is `unverified`, and no command contacts a shim.  A flight is a
label and a set of records, not a second scheduler or an authority.

### Flights and labels

`ozagia mesh ozma flight` reads the flight-scoped identity mapping records under
`identities/` and joins a local mesh registration by its key to report live
state.  A registration never declares a role.  `role` and `workunit` are
derived only from the host-provided `agent:<role>[:<workunit>]` id; without
that id both are `null`.  Registration order, link direction, WireGuard identity
and model claims are never used to infer a role, and no leader is elected.

The view reports the flight id/source, bounded members (harness/session/key,
agent id, role, workunit, scope, verification, transport, wake modes, state and
exposure), role/workunit counts, link/delegation counts whose two endpoints are
flight members, active advisory claims, open blocker edges, handoff and wake
counts, and readiness.  It is metadata only: no message bodies, criteria text,
credentials or card paths.  `dev_ozma_flight` exposes the same view on the
full/coding MCP surface and is read-only.

### Handoff lifecycle

Stage G's `handoff` mapping is unchanged.  An inbound `handoff` writes a
lifecycle record under
`<state>/mesh/ozma/handoffs/<flight>/<hash>.json` with state `pending`, the
sender, workunit, criteria digest/count, thread/channel and timestamps.  A
response queues a typed `ack` (`accept`/`reject`) or `handoff`
(`completion=done`) with the same thread and `in_reply_to` the handoff id; the
record moves to `accepted`, `rejected` or `complete` and keeps the ack id.  An
inbound `ack` whose `in_reply_to` names a handoff transitions it only when it
comes from the expected recipient.  Only the agent the handoff was addressed to
may accept or reject it, and only its sender may complete an outbound handoff;
any other local agent is refused.

Records are hashed, atomic, `0600` and bounded.  They retain no message body
beyond the bounded inbox.  A handoff acknowledgement never transfers a
credential, lease, delegation or merge authority; the record states
`authority_transferred: false` and the bridge does not touch a lease or
delegation.

`ozagia mesh ozma ack MESSAGE --accepted|--rejected` optionally queues a typed
ack for a message that declared `requires_ack`; the default `ack` remains
local-only.  There is no automatic reply.

### Advisory blockers

`<state>/mesh/ozma/blockers/<flight>.json` holds bounded edges
`{blocked_id, blocker_id, workunit, resource, state, created_at, cleared_at,
source}`.  `block`/`unblock` envelopes create and clear edges; the local
`block`/`unblock` commands do the same without a message.  `unblock --id`
matches an edge id or either party id, and `--workunit` clears a work unit.
Ids are validated; no arbitrary path is accepted.

A blocker is a warning shown in `flight` and `status`.  It never blocks a local
worktree, commit, merge, lease acquisition or policy check, and no command
grants merge authority.

### A2A lossy translation

`to_a2a(envelope)` produces a declared A2A v1.0-shaped message with a text part
and an `ozagia` metadata extension, and marks it `lossy: true` with named
fields.  It always names the static losses (`criteria`, `claim_scope`,
`blockers`, `subscriptions`, `priority_floor`, `compliance`) and adds `refs`
and `workunit` when present.  `from_a2a(payload)` rebuilds an untrusted inbound
envelope and reports the same loss list; structured criteria become flattened
text and refs/workunit are not restored.

A claim's scope or a block/unblock edge is a required field that A2A cannot
represent, so translation refuses with `a2a_unsupported_required` instead of
silently sending a message with a different meaning.  There is no A2A client:
no socket, DNS or HTTP is opened, and `sync`/`check --live` remain unavailable.
Because the adapter is declared rather than verified, `transport = "a2a"` is
not message-ready for `enqueue`/`claim`; the pure `to_a2a`/`from_a2a`
translation can still be exercised locally.

### Host-approved wake (primitives only)

`<state>/mesh/ozma/wake/<flight>/` holds approval and request records.
`wake approve` writes an approval only from the CLI:
`{mode: message-triggered|scheduled, budget_turns, used_turns, expires_at,
approved_by: host, source: cli, created_at}`.  It requires `budget_turns >= 1`,
a bounded TTL, a host-provided target agent id and the mode listed in
`[ozma_mesh] wake_modes`.  No model, MCP tool or daemon action can approve or
revoke wake.

An inbound envelope may declare `wake: "message"|"scheduled"` and an optional
`wake_at`.  The bridge records a pending request only after the message is
accepted, only when the target declares that mode, and never grants approval
from the envelope itself.

`wake claim` is a host-runner primitive.  It returns the next due request only
when an unexpired approval for the same target and mode has remaining budget;
it then increments `used_turns` and appends an id-only audit entry.  It refuses
with `wake_not_approved`, `wake_budget_exhausted`, `wake_expired`,
`wake_not_due` or `wake_mode_not_declared`.  It never spawns a process, model
turn, lease or timer; `claimable` is `true` and `spawnable` is `false`.
`status`/`check` report the same boundary and count pending requests.

## What comes next

A real live slice still needs an approved shim contract with host-supplied
authentication, a signed Agent Card verifier and an A2A client.  Until then the
bridge stays `declared`/`unverified`, `check --live` and `sync` stay
unavailable, and wake remains a host-runner primitive rather than a daemon
scheduler.  A TUI would be a read-only view over the same flight/status data;
it would not gain send, claim, approval, takeover or merge authority.
