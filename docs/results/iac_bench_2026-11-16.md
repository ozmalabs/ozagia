# Synthetic IaC benchmark — 2026-11-16

- Scope: synthetic offline benchmark; not production latency or model token evidence.
- Command: `.venv/bin/python -m ozagia.eval.iac_bench --files 300 --query-count 20`.
- Main run: 300 generated files (180 Terraform, 120 Kubernetes), seed 7, 20 warm samples/query kind.
- Generated at `2026-11-16T00:11Z`; Python 3.13.5, Linux x86_64.
- Source files: 190,183 bytes total; largest 1,349 bytes. Snapshot: 955,550 bytes enabled / 651 bytes disabled.
- Cold build, adapter enabled: 0.632 s wall; 2.479 s with tracemalloc tracing active; peak traced memory 5,383,494 bytes.
- Cold build, adapter disabled: 0.015 s wall; 0.029 s with tracing; peak 127,820 bytes.
- Synthetic enabled-minus-disabled build difference: 0.617 s. This is measured adapter overhead for this generated corpus, not an assumption of acceleration.
- Peak memory comes from a second build with the process-local parse cache cleared; it is not the same run as the untraced wall time.
- Enabled graph: 1,507 nodes, 2,466 edges, 1,205 InfraResource nodes, 961 infrastructure edges (840 Kubernetes).
- Warm query p50/p95 (nearest-rank, milliseconds):

  | Query | p50 | p95 | first call |
  | --- | ---: | ---: | ---: |
  | `infra.locate` | 0.131 | 0.151 | 14.009 |
  | `infra.context` | 1.239 | 1.300 | 1.447 |
  | `infra.dependencies` | 0.142 | 0.159 | 0.175 |

- The first `infra.locate` builds the token index; warm queries reuse it.
- Query-result cache after the mixed run: 81 entries, 8 hits, 81 misses (cache bound 128). Repeating the same `infra.context` request five times averaged 0.164 ms, including the cached-result deep copy, versus 1.239 ms p50 for the mixed warm queries.
- Refresh in the same process: modified Terraform 0.237 s; new Terraform 0.225 s (indexed); no-op 0.080 s. The per-file parse cache is process-local and bounded (6,000 entries); a refresh in a new process has to parse the corpus again.
- Freshness was `fresh` after build and each refresh. Both secret canaries were absent from the dump and query results.
- Context stayed within 480 characters (observed 406–479); `characters / 4` values are estimates, not tokenizer counts.
- Hardware-independent adapter budgets: 5,000 candidate files, 1 MiB/file, 16 MiB total source. None were hit.

## Scale check

A second run at 1,500 files (900 Terraform, 600 Kubernetes; 951,133 source
bytes; 6,005 InfraResource nodes and 4,801 infrastructure edges) measured
3.301 s cold wall and 27,728,352 peak traced bytes, with a 4,785,137-byte
snapshot. Warm p50/p95 was 0.133/0.156 ms for `infra.locate`, 5.407/5.676 ms
for `infra.context` and 0.141/0.164 ms for `infra.dependencies`; the first
`infra.locate` call, including index construction, took 69.853 ms. Refresh was
1.428 s for a modified Terraform file, 1.334 s for a new file and 0.318 s for a
no-op. Query-cache stats were the same 81 entries, 8 hits and 81 misses;
repeating one context request averaged 0.143 ms. None of the adapter budgets
were hit.

The infrastructure query index is built once per graph mutation and reused;
`locate` and `dependencies` look up by key or token rather than scanning every
node. Context remains the most expensive query because it scores candidates and
renders cited relationships, and it still grows with the number of matching
declarations. These scale numbers are still synthetic.

## Limits

- No model, infrastructure/cloud tool, external service, or cluster was called; local Git only established fixture freshness.
- These cold/warm synthetic measurements are not production evidence and establish no model-token savings.
